## Boot sequence (Gitea)

The image's own entrypoint and `s6-svscan /etc/s6` run unchanged (s6-svscan does not need to be PID 1, so Railway's podman-init is fine):

1. `gitea/setup`: first boot writes `app.ini` from the image template, then `environment-to-ini` applies every `GITEA__*` variable on every boot.
2. `openssh/setup`: host keys generated once into `/data/ssh` (persist across redeploys), sshd on port 22 (`SSH_LISTEN_PORT`).
3. `gitea web` as user `git`; `DB_RETRIES=60` while Postgres boots, and s6 restarts it if it still exits.
4. `railway-admin` (ours, one-shot via `s6-svc -O`): waits for `/api/healthz`, then `gitea admin user list --admin`; if none exists, `admin user create --admin --must-change-password=false` from `GITEA_ADMIN_*`. Optional `GITEA_ADMIN_PASSWORD_RESET=true` runs `change-password`. Invalid name → `gitea-admin`; invalid e-mail → `admin@example.com`; password < 8 → no admin, log line (fail closed, registration closed). Always exits 0 (STANDARD 8.29).

`INSTALL_LOCK=true` + generated `SECRET_KEY` skip the installer. `INTERNAL_TOKEN` and the JWT secrets are generated by Gitea and saved into `app.ini` on the volume.

## Improvements over market templates

Market (2026-11): `gitea/gitea` (no tag, SQLite on the volume, installer open) ≈92 active; Gitea+Postgres (`gitea:latest`, Postgres 17) ≈12 active; a repo-built Gitea+Postgres+Redis+MinIO variant ≈1 active.

- Official Gitea image pinned by tag + digest (market: `latest` or no tag).
- Postgres 18 instead of SQLite on the volume or Postgres 17; no MinIO (STANDARD: never MinIO), attachments and LFS on the volume.
- No web installer exposed on a public domain; first admin created from variables; registration closed by default (market `gitea/gitea` leaves the web installer, including the admin account form, open to the internet).
- SSH clone/push through a Railway TCP proxy with correct clone URLs (market: SSH disabled).
- `SECRET_KEY` generated, LFS on, healthcheck on `/api/healthz`, DB retries while Postgres boots.
- Deploy-form values never fail the deploy (8.29).

## Verification checklist

1. Both services SUCCESS; `GET /api/healthz` 200.
2. Log line `[railway-admin] Administrator 'gitea-admin' created`; API `GET /api/v1/user` with the variables → `is_admin: true`; wrong password → 401.
3. `/user/sign_up` says registration is disabled.
4. Create a repo through the API; add an SSH key; clone and push over `ssh://git@{tcp-proxy}:{port}/…`; raw file served over HTTPS.
5. `GITEA_ADMIN_PASSWORD=abc` + `RESET=true` → warning, service stays healthy; valid password + `RESET=true` → login works.
6. Redeploy: repository and admin persist.

## Open questions

- Gitea Actions runner not included: the runner needs Docker for job containers, which Railway services cannot run (STANDARD 8.32). A host-mode runner (no isolation) would be possible but is not offered.
- No built-in backup service: Railway volume backups or `gitea dump` are documented instead.
